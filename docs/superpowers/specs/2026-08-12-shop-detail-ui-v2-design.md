# 상점 상세 UI v2 설계

## 목표

Figma의 `상점 상세(229:2183)`를 현재 `dev` 코드와 디자인 토큰으로 새로 구현한다. 과거 `feat/36/shop-detail-ui` 구현은 복사하지 않고 테스트 항목과 사용자 흐름만 참고한다.

## 범위

- 경로: `/shops/[shopId]`
- Figma 순서대로 대표 이미지, 상점 기본 정보, 태그, 주요 행동, 위치, 운영 정보, 방문 후기 표시
- 좋아요는 화면의 로컬 상태로 전환
- `내 픽 추가`는 기존 `BottomSheet`에서 폴더를 선택하는 로컬 흐름 제공
- 정보 수정 제보는 기존 `BottomSheet`에서 사유를 선택하는 로컬 흐름 제공
- 후기 작성은 `/shops/[shopId]/reviews/new`로 이동
- API 연결과 서버 저장은 후속 이슈 범위로 제외

## 화면 구조

페이지는 동적 `shopId`를 받는 Server Component로 유지하고, fixture를 안전한 표시 모델로 고른다. 좋아요와 바텀시트처럼 상호작용이 필요한 영역만 Client Component로 둔다.

화면 컴포넌트는 다음 책임으로 나눈다.

- `ShopDetailScreen`: 화면의 세로 흐름과 상태 조합
- `ShopDetailHero`: 대표 이미지와 뒤로가기·좋아요·제보 행동
- `ShopSummary`: 상점명, 분류, 태그와 집계 정보
- `ShopLocation`: 위치 안내와 지도 미리보기
- `ShopHours`: 영업시간과 휴무일
- `VisitReviewList`: 후기 목록, 빈 상태와 후기 작성 이동
- `ShopDetailActions`: 내 픽과 제보 바텀시트의 로컬 상태

## Modal 제거 규칙

공용 Modal을 만들거나 사용하지 않는다. Figma의 `상점 상세: 제보완료 모달(216:1951)`은 제보 바텀시트 안의 완료 단계로 바꾼다.

제보 사유를 선택하고 `제보하기`를 누르면 같은 바텀시트의 내용이 체크 아이콘, `제보가 접수되었어요` 문구와 `닫기` 버튼으로 교체된다. 닫은 뒤 다시 열면 사유 선택 단계로 초기화한다. 처리 중 중복 제출은 막는다.

## 데이터와 방어 상태

화면 전용 fixture와 표시 타입은 기능 폴더 가까이에 둔다. 이미지·태그·주소·영업 정보·후기는 누락될 수 있는 값으로 다루고 안전한 대체 UI를 제공한다.

Storybook에서 `success`, `loading`, `empty`, `error`, 긴 콘텐츠와 깨진 이미지 상태를 제공한다. 라우트에는 최종 레이아웃과 비슷한 `loading.tsx`와 복구 버튼이 있는 `error.tsx`를 둔다.

## 접근성과 반응형

- 아이콘 버튼에는 목적이 드러나는 접근 가능한 이름을 제공한다.
- 좋아요의 선택 상태는 `aria-pressed`로 전달한다.
- BottomSheet는 Escape 닫기, 초점 가두기와 트리거 초점 복구를 기존 구현으로 유지한다.
- 완료 단계는 `role="status"`로 알린다.
- 320px, 390px, 480px에서 가로 넘침 없이 표시한다.
- Figma의 393px 비율을 중심으로 하되 고정 너비 대신 앱 프레임에 맞는 유동 너비를 사용한다.

## 시각 구현 규칙

기존 색상·타이포그래피 토큰과 공용 `Badge`, `Button`, `BottomSheet`, `Skeleton`을 먼저 사용한다. Figma 임시 URL은 운영 코드에 남기지 않고 필요한 이미지는 저장소의 로컬 자산으로 둔다. 상태바는 브라우저 UI이므로 구현하지 않는다.

## 검증 기준

- 상점 정보, 좋아요, 내 픽 선택, 제보 선택·완료, 후기 작성 이동을 Storybook 상호작용 테스트로 확인
- 로딩·빈 상태·오류 상태와 누락 필드 렌더링 확인
- 320px, 390px, 480px의 화면, 키보드, 포커스와 콘솔 오류 확인
- `frontend` Storybook 테스트, 린트와 빌드 통과
- `git diff --check`와 변경 파일 범위 확인
