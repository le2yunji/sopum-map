# 내 픽 상점 폴더 변경 설계

## 의도

내 픽 목록에서 상점 상세 화면을 거치지 않고 폴더 소속을 바로 바꾼다. 상점은 여러 폴더에 속할 수 있으므로 단일 이동이 아니라 현재 소속을 체크박스로 편집한다.

## 범위

- 전체 탭과 특정 폴더 탭의 상점 이름 오른쪽에 세로 케밥 버튼을 둔다.
- 케밥 버튼을 누르면 중간 메뉴 없이 해당 상점의 폴더 선택 바텀시트를 바로 연다.
- 상점 상세 링크와 케밥 버튼의 클릭 영역을 분리한다.
- `PicksScreen`이 선택한 `shopId`와 `PickFolderSheet` 한 개를 소유한다.
- 기존 `PUT /me/liked-shops/:shopId/folders`와 `useUpdateFolderIdsByShop`을 재사용한다.
- 저장 성공 뒤 폴더 목록과 폴더별 상점 쿼리를 갱신한다.
- 저장 실패 시 시트를 유지하고 같은 저장 버튼으로 다시 시도할 수 있게 한다.

## 제외 범위

- 여러 상점 일괄 변경
- 드래그 앤 드롭
- 새 백엔드 API 또는 데이터 모델
- 폴더 생성·수정·삭제 흐름 변경

## 접근 방식

1. **선택: `PicksScreen`에 공유 시트 한 개 배치.** 화면이 선택 상점 상태를 소유하므로 전체 탭과 폴더 탭에서 같은 흐름을 사용하고, 닫힌 시트와 쿼리가 카드 수만큼 생기지 않는다.
2. `PickShopGrid`가 시트를 소유하는 방식은 가능하지만 화면 수준 동작이 목록 컴포넌트 안에 숨는다.
3. 카드마다 시트를 두는 방식은 카드 수만큼 상태와 쿼리 훅이 생기므로 사용하지 않는다.

## 상호작용과 상태

- 카드의 상세 링크와 케밥 버튼은 서로 중첩하지 않는다.
- 케밥 버튼의 접근 가능한 이름은 시각 모양이 아니라 실제 동작인 `상점명 폴더 이동`으로 제공한다.
- 케밥 버튼을 누르면 화면에 상점 ID를 바로 전달한다.
- `PicksScreen`의 `selectedShopId`가 `null`이면 시트를 렌더링하지 않는다.
- 버튼을 누르면 해당 상점 ID를 저장하고 시트를 연다.
- 시트가 닫히면 선택 상점 ID도 `null`로 되돌린다.
- 요청 중에는 저장 버튼을 비활성화한다.
- 현재 폴더 체크를 해제해 저장하면 기존 쿼리 무효화로 활성 폴더 목록을 다시 받아 해당 카드를 제거한다.

## 검증

- 카드의 상세 링크와 폴더 변경 버튼을 키보드와 접근 가능한 이름으로 구분한다.
- Storybook 상호작용 테스트로 시트 열기, 기존 소속 표시, 저장 성공 후 현재 폴더에서 제거, 저장 실패 후 재시도를 검증한다.
- 320px, 390px, 480px 뷰포트에서 카드 액션이 잘리지 않는지 확인한다.
