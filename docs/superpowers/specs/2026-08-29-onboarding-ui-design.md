# 온보딩 UI 설계

## 목적

첫 방문자가 소품지도의 핵심 기능을 짧게 이해한 뒤 홈에서 바로 상점을 둘러보게 한다. 로그인은 온보딩에서 요구하지 않는다. 저장이나 후기 작성처럼 계정이 필요한 행동을 시작할 때 별도로 안내한다.

## 사용자 흐름

1. 앱 진입 직후 버튼 없는 브랜드 스플래시를 약 1.5초 보여준다.
2. 온보딩 완료 쿠키가 없는 첫 사용자는 온보딩 첫 페이지로 이동한다.
3. 첫 사용자는 네 페이지를 순서대로 살펴본다.
4. 마지막 페이지의 `소품지도 시작하기` 버튼을 누르면 완료 쿠키를 저장하고 홈으로 이동한다.
5. 완료 쿠키가 있는 사용자는 온보딩 경로를 거치지 않고 요청한 화면을 이용한다.

완료 쿠키는 마지막 버튼을 누를 때만 저장한다. 사용자가 중간에 페이지를 닫으면 다음 방문에도 온보딩을 다시 보여준다.

## 화면 구성

모든 화면은 기존 색상 토큰, 공용 `Button`, 로컬 브랜드 이미지를 재사용한다. 마스코트가 중심이 되는 카드형 구성을 사용한다. 모바일 앱 프레임의 320px부터 480px까지 자연스럽게 맞춘다.

### 스플래시

- 기존 Figma의 `스플래시: 소품지도` 프레임을 기준으로 한다.
- 마스코트, `소품지도`, `행운을 찾는 소품산책`, 저작권 문구를 표시한다.
- 배경의 연한 초록빛 장식을 유지한다.
- 버튼, 페이지 표시점, 사용자 입력은 두지 않는다.
- 장식 애니메이션은 `prefers-reduced-motion` 설정을 존중한다.

### 온보딩 1: 발견

- 제목: `취향에 맞는 소품샵을 발견해요`
- 설명: 지역과 취향 태그로 나에게 맞는 소품샵을 찾는 기능을 소개한다.
- 마스코트와 상점 탐색을 떠올릴 수 있는 기존 이미지를 조합한다.

### 온보딩 2: 내 픽

- 제목: `마음에 드는 곳은 내 픽에 모아요`
- 설명: 다시 찾고 싶은 상점을 저장하고 모아보는 기능을 소개한다.
- 마스코트와 하트 또는 저장 상태를 나타내는 기존 아이콘을 사용한다.

### 온보딩 3: 코스

- 제목: `소품샵을 나만의 코스로 이어봐요`
- 설명: 여러 상점을 한 번의 산책 코스로 구성하는 기능을 소개한다.
- 기존 위치·지도 아이콘과 브랜드 이미지를 사용한다.

### 온보딩 4: 방문 기록

- 제목: `다녀온 추억을 기록해요`
- 설명: 방문한 상점에 사진과 후기를 남기는 기능을 소개한다.
- 마스코트와 기존 카메라·후기 아이콘을 사용한다.
- 기본 버튼 문구를 `소품지도 시작하기`로 바꾼다.

## 탐색과 상태

- 첫 세 페이지에는 `이전`과 `다음` 버튼을 제공한다. 첫 페이지의 `이전` 버튼은 표시하지 않는다.
- 네 개의 페이지 표시점으로 현재 위치를 시각적으로 알린다. 보조 기술에는 `4페이지 중 2페이지`처럼 텍스트로 전달한다.
- 좌우 스와이프와 키보드의 왼쪽·오른쪽 방향키로 이동할 수 있다.
- 페이지 범위를 벗어나는 이동은 무시한다.
- 페이지를 바꾸면 새 제목으로 초점을 옮겨 화면 읽기 도구 사용자가 변화를 알 수 있게 한다.
- 현재 페이지는 브라우저 저장소에 남기지 않는다. 새 온보딩 방문은 첫 페이지에서 시작한다.

## 컴포넌트 경계

- `OnboardingScreen`: 스플래시와 온보딩 단계 전환, 완료 동작을 조합한다.
- `BrandSplashScreen`: 버튼 없는 브랜드 스플래시만 표시한다.
- `OnboardingCarousel`: 현재 페이지, 이전·다음·스와이프·키보드 이동을 관리한다.
- `OnboardingSlide`: 한 페이지의 이미지, 제목, 설명을 표시한다.
- 정적인 페이지 문구와 이미지 정보는 별도 상수로 두어 화면 구조와 분리한다.

스플래시 타이머와 쿠키 문자열 생성은 기존 온보딩 유틸리티를 확장해 화면 컴포넌트가 세부 구현을 알지 않게 한다.

## 예외와 안전 처리

- 온보딩 완료 목적지는 홈으로 고정해 외부 사이트로 이동할 여지를 두지 않는다.
- 완료 버튼을 연속으로 눌러도 쿠키 저장과 이동은 한 번만 처리한다.
- 이미지에는 의미에 맞는 대체 텍스트를 제공한다. 순수 장식은 보조 기술에서 숨긴다.
- 온보딩 경로에서 오류가 생기면 기존 `error.tsx`가 다시 시도 동작을 제공한다.

## 검증

- 스플래시 시간이 끝나기 전에는 온보딩이 보이지 않는지 단위 테스트한다.
- 완료 쿠키가 없는 사용자가 네 페이지를 순서대로 이동할 수 있는지 테스트한다.
- 마지막 버튼을 누르기 전에는 쿠키가 저장되지 않는지 테스트한다.
- 마지막 버튼을 한 번 누르면 쿠키를 저장하고 홈으로 이동하는지 테스트한다.
- 이전·다음, 방향키, 스와이프와 페이지 범위 처리를 테스트한다.
- Storybook에서 320px, 390px, 480px 배치와 키보드·포커스 동작을 확인한다.
- 프론트엔드 단위 테스트, Storybook 테스트, 린트, 빌드와 `git diff --check`를 실행한다.

## 범위 밖

- 로그인 또는 회원가입 흐름 변경
- 로그인 필요 기능의 인증 안내 구현
- 온보딩 진행 위치 저장
- 서버 계정에 온보딩 완료 상태 저장
- 새로운 외부 UI·애니메이션 라이브러리 도입
