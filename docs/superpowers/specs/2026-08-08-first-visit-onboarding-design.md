# 첫 방문 온보딩 이동 흐름 설계

## 목표

같은 브라우저에서 소품지도를 처음 방문한 사용자에게 온보딩 화면을 한 번 보여준다. 이후 방문에서는 온보딩을 건너뛰고 원래 요청한 페이지를 바로 표시한다.

## 범위

- 첫 방문 판정 대상은 홈(`/`)과 로그인(`/login`)이다.
- 온보딩 완료 여부는 브라우저 쿠키에 1년 동안 저장한다.
- 삭제된 온보딩 페이지, 화면 컴포넌트, 로딩·오류 UI와 Storybook 스토리를 기존 상태로 복구한다.
- 온보딩은 로딩 화면이나 `Suspense` fallback으로 사용하지 않는다.
- 인증 및 사용자 계정별 온보딩 상태는 이번 범위에 포함하지 않는다.

## 사용자 흐름

1. 사용자가 `/` 또는 `/login`을 요청한다.
2. `src/proxy.ts`가 `sopum_onboarding_completed` 쿠키를 확인한다.
3. 쿠키가 없으면 `/onboarding?next=<원래 경로>`로 리다이렉트한다.
4. 사용자가 `시작하기` 또는 `로그인하기`를 선택한다.
5. 브라우저에 완료 쿠키를 저장한다.
6. `시작하기`는 안전하게 검증한 `next` 경로로 이동한다.
7. `로그인하기`는 `/login`으로 이동한다.
8. 이후 `/`와 `/login` 요청은 온보딩을 건너뛴다.

## 구조

### `frontend/src/proxy.ts`

Next.js 16의 Proxy 규칙을 사용한다. matcher는 `/`와 `/login`으로 제한한다. 정적 파일이나 API 요청에는 실행하지 않는다.

쿠키가 없을 때만 `/onboarding`으로 리다이렉트한다. 원래 목적지는 `next` 쿼리로 전달한다.

### `frontend/src/app/onboarding/page.tsx`

검색 노출 방지 메타데이터를 유지한다. `searchParams.next`를 읽고 안전한 내부 경로로 정규화한 뒤 화면 컴포넌트에 전달한다.

외부 URL이나 `//example.com` 같은 프로토콜 상대 URL은 허용하지 않는다. 허용되지 않은 값은 홈(`/`)으로 대체한다.

### `frontend/src/app/onboarding/_components/OnboardingScreen.tsx`

기존 온보딩 UI를 복구하고 사용자 상호작용 때문에 클라이언트 컴포넌트로 전환한다.

- `시작하기`: 완료 쿠키를 기록하고 전달받은 목적지로 `router.replace`한다.
- `로그인하기`: 완료 쿠키를 기록하고 `/login`으로 `router.replace`한다.
- 링크 대신 버튼을 사용하여 쿠키 기록이 먼저 실행되도록 한다.

쿠키 속성은 `Path=/`, `Max-Age=31536000`, `SameSite=Lax`를 사용한다. HTTPS 환경에서는 `Secure`를 함께 사용한다. 브라우저 JavaScript가 기록해야 하므로 `HttpOnly`는 사용할 수 없다.

### `frontend/src/app/onboarding/loading.tsx`

기존 스켈레톤 UI를 복구한다. 온보딩 라우트 자체가 준비될 때만 사용하며 첫 방문 판정 수단으로 사용하지 않는다.

### `frontend/src/app/onboarding/error.tsx`와 Storybook 스토리

기존 오류 복구 UI와 화면 크기별 Storybook 검증을 함께 복구한다. 첫 방문 이동에 맞춰 버튼 동작 테스트를 갱신한다.

### 기존 로딩 관련 사용자 변경

현재 작업 트리에 추가된 공용 로딩 컴포넌트와 로그인 로딩 파일은 삭제하거나 덮어쓰지 않는다. 첫 방문 온보딩은 로딩 처리와 분리하며, 해당 파일이 빌드와 새 이동 흐름에 충돌할 때만 최소 범위로 조정한다.

## 오류와 보안

- `next`는 `/`로 시작하는 내부 경로만 허용한다.
- `//`로 시작하는 값은 외부 호스트로 이동할 수 있으므로 거부한다.
- 쿠키 기록 뒤 이동하므로 `/login`과 `/` 사이의 리다이렉트 반복을 막는다.
- Proxy matcher를 두 경로로 제한하여 이미지와 Next.js 내부 자산을 방해하지 않는다.

## 테스트

- Proxy 단위 테스트
  - 쿠키가 없는 `/` 요청은 `/onboarding?next=%2F`로 이동한다.
  - 쿠키가 없는 `/login` 요청은 원래 목적지를 보존한다.
  - 완료 쿠키가 있으면 요청을 그대로 통과시킨다.
- 목적지 검증 테스트
  - `/`와 `/login` 같은 내부 경로를 허용한다.
  - 외부 URL, 프로토콜 상대 URL, 빈 값을 `/`로 대체한다.
- 온보딩 화면 테스트
  - 두 버튼이 보인다.
  - 시작하기와 로그인하기가 완료 쿠키를 기록한다.
  - 각 버튼이 올바른 목적지로 이동한다.
- 프론트엔드 lint와 build를 실행한다.

## 완료 기준

- 첫 방문 브라우저에서 `/`와 `/login`이 온보딩으로 이동한다.
- 온보딩을 완료한 같은 브라우저에서는 다시 표시되지 않는다.
- 원래 목적지가 안전하게 보존된다.
- 기존 온보딩 UI와 접근성을 유지한다.
- 관련 테스트, lint, build가 통과한다.
