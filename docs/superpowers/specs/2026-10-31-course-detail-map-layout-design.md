# 코스 상세 전체 지도 UI 설계

## 목적

`/courses/[courseId]`를 세로 문서형 화면에서 지도 중심 화면으로 바꾼다. 사용자는 코스 전체 위치를 먼저 보고, 필요한 때 방문 순서를 펼쳐 확인할 수 있어야 한다.

## 목표와 제외 범위

- 네이버 지도가 모바일 앱 영역 전체를 채운다.
- 코스 제목, 지역, 작성자, 날짜, 설명, 공개 상태 또는 좋아요 액션을 지도 위 반투명 정보 카드로 표시한다.
- 방문 순서는 하단의 접힘·펼침 가능한 2단 시트로 표시한다.
- 뒤로가기, 공유, 더보기와 기존 상점·방문 액션을 유지한다.
- 기존 TMAP 경로 좌표 연동과 실제 도보 Polyline 정책 변경은 이번 범위에 포함하지 않는다.
- API 계약과 백엔드는 변경하지 않는다.

## 선택한 접근

### 선택: 지도 페이지와 같은 2단 고정 시트

접힌 상태에서는 손잡이, `방문 순서`, 상점 수와 첫 방문 항목 일부를 보여준다. 사용자가 손잡이를 누르거나 위로 끌면 시트가 펼쳐지고, 목록을 내부에서 스크롤할 수 있다. 아래로 끌면 다시 접힌다.

이 방식을 선택한 이유는 지도와 목록을 한 화면에서 오갈 수 있고, 사용자가 추천한 지도 중심 경험을 가장 잘 유지하기 때문이다.

### 검토한 대안

- 고정 높이 시트: 구현은 단순하지만 상점이 많을 때 목록을 보기 어렵고 지도를 넓게 쓰기 어렵다.
- 대화상자형 공용 `BottomSheet`: 포커스 가두기와 배경 딤이 필요한 일시적 작업에 맞는다. 항상 보이는 방문 순서에는 맞지 않는다.

## 화면 구조

1. 최상위 화면은 `h-dvh`, `overflow-hidden`인 지도 컨테이너다.
2. `CourseMap`은 둥근 카드가 아니라 컨테이너 전체를 채운다. 지도 조작은 사용자가 확대·이동할 수 있도록 활성화한다.
3. 상단에는 안전 영역을 고려한 오버레이를 둔다.
   - 첫 줄: 뒤로가기, 공유, 소유자 더보기
   - 정보 카드: 지역, 제목, 작성자·날짜, 설명, 공개 상태 또는 좋아요
   - 카드 모양: 디자인 토큰의 둥근 모서리, 흰색 반투명 배경, 약한 그림자와 배경 블러
   - 정보 카드에는 닫기 버튼을 둔다. 닫으면 상단 액션은 유지하고 작은 `코스 정보` 버튼을 표시한다.
   - `코스 정보` 버튼을 누르면 정보 카드가 원래 위치에 다시 열린다.
4. 하단에는 `CourseVisitOrderSheet`를 둔다.
   - 접힘 높이는 지도 페이지와 비슷한 약 200px
   - 펼침 상태에서도 상단 정보 카드와 겹치지 않도록 위쪽 여백을 남긴다.
   - 기존 `CourseDetailShopItem`과 상점 액션 연결을 그대로 사용한다.
5. 삭제, 공개 전환, 상점 액션, 방문 로그 확인용 대화상자형 바텀시트는 현재 공용 `BottomSheet` 동작을 유지하며 고정 방문순서 시트보다 위에 표시한다.

## 컴포넌트 경계

- `CourseDetailScreen`: 데이터, 뮤테이션, 오버레이와 시트 조합을 담당한다.
- `CourseDetailHeader`: 지도 위 상단 액션과 코스 정보 카드 표현을 담당하도록 스타일과 구조를 조정한다.
- `CourseMap`: 전체 크기 지도와 마커·Polyline만 담당한다.
- `CourseVisitOrderSheet`: 접힘·펼침 상태, 제스처, 방문 순서 목록을 담당한다.
- 제스처 계산은 작은 순수 함수로 분리해 단위 테스트한다. 지도 상점 목록 전용 훅에 코스 타입을 억지로 결합하지 않는다.

## 상태와 접근성

- 초기 상태는 `collapsed`로 둔다.
- 손잡이 전체를 버튼으로 만들고 `aria-expanded`, 펼치기/접기 이름을 제공한다.
- 정보 카드 닫기 버튼과 `코스 정보` 복원 버튼에 접근 가능한 이름을 제공한다.
- 클릭과 키보드 Enter/Space로도 상태를 바꿀 수 있다.
- 드래그 중 목록 항목 클릭이 잘못 실행되지 않게 한다.
- `prefers-reduced-motion`에서는 스냅 애니메이션을 끈다.
- 320px, 390px, 480px에서 긴 제목과 설명이 카드 밖으로 넘치지 않게 한다.
- 로딩과 오류 화면도 전체 화면 높이를 유지한다.

## 검증

- 시트 상태 결정 순수 함수의 단위 테스트를 먼저 작성한다.
- Storybook에서 타인 코스, 내 코스, 추천 코스와 상점 액션 흐름을 유지한다.
- Storybook 상호작용 테스트로 시트 펼침·접힘과 접근 가능한 이름을 확인한다.
- 320px, 390px, 480px에서 상단 카드, 지도, 접힌/펼친 시트의 겹침을 확인한다.
- 프론트엔드 단위 테스트, Storybook 테스트, 린트, 빌드와 `git diff --check`를 실행한다.
