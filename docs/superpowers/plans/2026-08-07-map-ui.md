# Map UI Implementation Plan

**Goal:** Implement issue #30 as a resilient Naver Map screen with connected local markers, filters, and shop results.

**Architecture:** Keep the Naver Maps script loader and map adapter isolated from the screen display model. The screen owns local search, category, tag, and selected-shop state. SDK loading, missing configuration, empty results, and section errors have explicit UI states.

## Constraints

- Use `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID`; never commit a real client ID.
- Include the Naver Maps engine and fixture-coordinate markers in #30.
- Leave real shop APIs and current-location lookup to #31.
- Preserve the shared bottom navigation and 320px–480px mobile layout.
- Add short purpose comments above new functions.
