# 코스 페이지 기능 설명

## 1. 목적

사용자가 내 픽 폴더에 저장한 소품샵을 방문 순서가 있는 하나의 코스로 구성하고, 생성한 코스를 다시 조회·수정·삭제할 수 있게 한다.

1차 구현은 개인 코스 관리에 집중한다. 다른 사용자에게 코스를 공개하는 기능과 실제 이동 경로 계산은 후속 범위로 분리한다.

## 2. 핵심 규칙

- 하나의 내 픽 폴더는 삭제되지 않은 코스를 최대 하나만 가진다.
- 폴더에 연결된 코스가 이미 있으면 새 코스를 만들지 않고 기존 코스 편집 화면으로 이동한다.
- 코스는 생성 시점의 폴더 상태를 복사한 뒤 원본 폴더와 독립적으로 관리한다.
- 코스를 만든 뒤 폴더의 상점이 바뀌어도 기존 코스는 자동으로 바뀌지 않는다.
- `전체` 픽 목록에서는 코스를 만들 수 없다. 특정 폴더를 선택해야 한다.
- 코스에는 최소 2개, 최대 10개의 상점이 필요하다.
- 생성된 사용자 코스는 1차 구현에서 항상 비공개다.

## 3. 데이터 의미

### 코스 구분 필드

| 필드             | 의미                                       | 1차 구현 값    |
| ---------------- | ------------------------------------------ | -------------- |
| `courseType`     | 사용자 생성 코스인지 추천 코스인지 구분    | `user_created` |
| `sourceFolderId` | 코스 생성에 사용한 원본 내 픽 폴더         | 선택한 폴더 ID |
| `isPublic`       | 다른 사용자가 코스를 조회할 수 있는지 구분 | `false`        |

`isPublic`은 출처 필드가 아니라 공개 범위 필드다. 공개 코스 기능을 구현할 때 그대로 사용한다.

### 현재 모델에서 바로잡아야 할 부분

공용 상수의 코스 유형은 `user_created | recommended`인데 현재 Course 모델 일부는 `user`를 기본값과 필수 조건으로 사용한다. 구현 전에 모델 기본값과 조건을 공용 상수에 맞춰야 한다.

대표 지역은 자유 문자열 `region` 대신 상점과 같은 공용 `regionGroup` 타입을 사용한다. 1차 구현에서는 현재 `SHOP_REGION_GROUPS`에 정의된 `성수·서울숲`, `홍대·연남`, `망원`, `서촌`만 사용하며 새로운 지역 키워드는 추가하지 않는다.

## 4. 사용자 흐름

### 신규 코스 생성

```text
내 픽 화면
→ 특정 폴더 선택
→ 폴더 속 샵으로 코스 만들기
→ /courses/new?folderId={folderId}
→ 코스 내용 편집
→ 코스 만들기
→ /courses/{courseId}
```

- 코스는 생성 화면에 진입할 때 만들지 않는다.
- 사용자가 `코스 만들기`를 눌러 유효한 요청을 제출했을 때만 데이터베이스에 저장한다.
- 저장 성공 후 생성된 코스 상세 화면으로 이동한다.
- 상세 화면에서 `코스가 만들어졌어요` 안내를 잠시 표시한다.

### 기존 코스가 있는 폴더

- 프론트엔드는 폴더에 연결된 기존 코스를 확인한다.
- 기존 코스가 있으면 `/courses/{courseId}/edit`로 이동한다.
- 폴더에 연결된 코스가 없으면 작업 메뉴 문구를 `폴더 속 샵으로 코스 만들기`로 표시한다.
- 폴더에 연결된 코스가 있으면 작업 메뉴 문구를 `코스 수정하기`로 표시한다.
- 프론트엔드의 임시 상태로 문구를 추측하지 않고, 서버가 제공한 기존 `courseId`를 기준으로 생성과 수정을 구분한다.
- `코스 수정하기`를 누를 때 폴더의 현재 상점 구성을 기존 코스에 자동 반영하지 않는다.
- 동시에 여러 화면이나 기기에서 생성 요청이 들어와도 백엔드의 고유 제약으로 중복 생성을 막는다.
- 생성 경쟁으로 충돌하면 일반 오류만 보여주지 않고 기존 코스 편집 화면으로 안내한다.

### 전체 픽 탭과 생성 불가능한 폴더

- `전체` 탭에서는 코스 생성 동작을 제공하지 않는다.
- 상점이 2개보다 적은 폴더에서는 생성 동작을 비활성화한다.
- 비활성화 이유로 `코스를 만들려면 상점이 2개 이상 필요해요`를 표시한다.

## 5. 코스 생성·편집 화면

### 기본 입력값

- 제목은 폴더명으로 자동 입력하고 사용자가 수정할 수 있다.
- 설명은 선택 입력이다.
- 폴더에 상점이 10개 이하면 모든 상점을 기본으로 선택한다.
- 폴더에 상점이 10개보다 많으면 추가된 순서가 빠른 10개를 기본으로 선택하고 나머지는 미선택으로 표시한다.
- 상점은 폴더에 추가된 순서대로 배치한다.
- `PickFolderItem.createdAt` 오름차순을 최초 방문 순서로 사용한다.

### 상점 선택

- 생성 시 원본 폴더의 상점을 최대 10개까지 선택할 수 있다.
- 원본 폴더에 상점이 10개보다 많으면 사용자가 코스에 포함할 상점을 고른다.
- 최종 선택이 2개보다 적으면 저장할 수 없다.
- 생성 후 코스 편집에서는 현재 내 픽에 저장된 모든 상점 중 새 상점을 추가할 수 있다.
- 코스는 원본 폴더와 독립적이므로 편집 화면에서 상점을 제외하거나 새로 추가할 수 있다.

### 방문 순서

- 터치 환경에서는 드래그로 방문 순서를 변경한다.
- 키보드와 보조 기술 사용자를 위해 위로 이동·아래로 이동 버튼을 함께 제공한다.
- 화면에 표시된 순서를 `Course.shops[].order`에 1부터 연속된 숫자로 저장한다.

### 상점별 메모

- 각 상점에 선택적으로 메모를 작성할 수 있다.
- 예: `점심 전에 방문`, `스티커 코너 확인`.
- 메모는 현재 모델 기준 최대 300자다.

### 편집 가능한 항목

- 코스 제목
- 코스 설명
- 코스에 포함할 상점
- 방문 순서
- 상점별 메모

`sourceFolderId`는 출처 기록이므로 편집할 수 없다.

### 작성 중 이탈

- 사용자가 내용을 변경한 뒤 화면을 나가려고 하면 `작성 중인 내용이 사라져요` 확인창을 표시한다.
- 1차 구현에서는 임시 저장과 자동 저장을 제공하지 않는다.

## 6. 대표 지역 결정

선택된 상점의 `regionGroup`을 기준으로 다음 순서로 대표 지역을 결정한다.

1. 가장 많은 상점이 속한 지역을 사용한다.
2. 최다 지역이 여러 개면 방문 순서가 가장 빠른 상점의 지역을 사용한다.
3. 상점의 지역 정보가 누락되면 서울 같은 임의 기본값을 사용하지 않고 생성 오류로 처리한다.

예시:

| 코스 구성                 | 대표 지역           |
| ------------------------- | ------------------- |
| 성수·서울숲 2곳, 망원 1곳 | 성수·서울숲         |
| 홍대·연남 1곳, 서촌 1곳   | 첫 번째 상점의 지역 |
| 망원 2곳                  | 망원                |

## 7. 코스 상세 화면

### 표시 정보

- 코스 제목
- 코스 설명
- 대표 지역
- 방문 순서
- 상점 기본 정보
- 상점별 메모
- 상점 상세 화면 링크
- 상점별 네이버 지도 길찾기 링크

### 지도

1차 구현에는 여러 상점을 잇는 실제 경로 API가 없다.

- 지도에 방문 순서가 표시된 마커를 배치한다.
- 마커를 방문 순서대로 직선으로 연결한다.
- 직선은 실제 도보 경로가 아니라는 안내를 표시한다.
- 실제 계산값이 없으므로 전체 거리와 예상 소요 시간 영역은 숨긴다.
- 각 상점에서 기존 네이버 지도 길찾기 링크를 사용할 수 있다.

### 이용 불가능한 상점

코스에 포함된 상점이 폐점 또는 비활성 상태가 되어도 코스에서 자동으로 삭제하지 않는다.

- 상세 화면에 `현재 이용할 수 없는 상점`으로 표시한다.
- 코스 편집 화면에서 사용자가 직접 제거할 수 있다.
- 상점 상태 변경 때문에 방문 순서와 작성자의 기록을 자동으로 바꾸지 않는다.

## 8. 내 코스 목록

- 마이페이지의 `/me/courses`에서 사용자가 만든 코스 목록을 제공한다.
- 코스 항목을 누르면 해당 코스 상세 화면으로 이동한다.
- 1차 구현의 모든 코스는 비공개이므로 작성자 본인에게만 표시한다.
- 홈의 추천 코스 영역에는 사용자 비공개 코스를 노출하지 않는다.

## 9. 삭제와 원본 폴더의 관계

### 원본 폴더 삭제

- 원본 폴더를 삭제해도 생성된 코스는 유지한다.
- 연결된 코스의 `sourceFolderId`만 `null`로 정리한다.
- 코스에 복사된 상점, 순서와 메모는 유지한다.

### 코스 삭제

- 코스 삭제 전 확인창을 표시한다.
- 코스가 삭제되면 해당 폴더의 코스 고유 제약이 풀린다.
- 사용자는 같은 폴더로 새 코스를 다시 만들 수 있다.

## 10. 접근 권한

- 인증되지 않은 사용자가 내 코스 API에 접근하면 `401`을 반환한다.
- 다른 사용자의 비공개 코스에 접근하면 `403`을 반환한다.
- 코스 작성자만 코스를 수정하거나 삭제할 수 있다.
- 다른 사용자의 내 픽 폴더로 코스를 만들 수 없다.
- 다른 사용자의 폴더를 사용한 생성 요청에는 기존 폴더 접근 정책과 같은 `403`을 반환한다.

## 11. 백엔드 책임

1차 구현은 다음 기능을 하나의 완성된 흐름으로 제공한다.

- 폴더 기반 코스 생성
- 코스 상세 조회
- 내 코스 목록 조회
- 코스 수정
- 코스 삭제
- 폴더 및 코스 소유자 검증
- 상점 존재 여부와 상태 확인
- 상점 개수와 중복 검증
- 방문 순서 검증
- 대표 지역 계산
- 폴더당 삭제되지 않은 코스 하나 보장
- 폴더 삭제 시 `sourceFolderId` 정리

### 고유성 보장

프론트엔드 확인만으로 중복 생성을 막지 않는다. 사용자 생성 코스 중 `sourceFolderId`가 존재하는 문서에 대해 사용자와 원본 폴더 조합이 고유하도록 데이터베이스 인덱스를 둔다.

원본 폴더가 삭제되어 `sourceFolderId`가 `null`인 코스는 고유성 대상에서 제외한다.

### 생성 API 입력

생성 요청에는 최소한 다음 값이 필요하다.

- `sourceFolderId`
- `title`
- `description`
- 선택한 상점 ID 목록
- 상점별 방문 순서
- 상점별 선택 메모

서버는 클라이언트가 보낸 대표 지역을 신뢰하지 않고 선택된 상점 데이터로 직접 계산한다. `courseType`과 `isPublic`도 1차 정책에 따라 서버에서 각각 `user_created`, `false`로 저장한다.

## 12. 오류 처리

- 코스 생성·수정 실패 시 사용자가 입력한 제목, 설명, 순서와 메모를 유지한다.
- 화면 안에서 오류 원인을 안내하고 `다시 시도` 동작을 제공한다.
- 상점이 2개보다 적거나 10개보다 많으면 저장하지 않는다.
- 같은 상점을 중복으로 포함할 수 없다.
- 방문 순서는 1부터 상점 개수까지 중복 없이 연속되어야 한다.
- 존재하지 않는 상점은 코스에 추가할 수 없다.
- 지역 정보가 없는 상점으로 코스를 생성할 수 없다.
- 같은 폴더의 코스가 이미 있으면 기존 `courseId`를 식별할 수 있는 충돌 응답을 제공한다.

## 13. 1차 구현에서 제외하는 기능

- 다른 사용자에게 코스 공개
- 공개 코스 목록과 검색
- 공개 코스 신고와 관리
- 실제 도보·대중교통 경로 계산
- 실제 전체 거리와 예상 소요 시간
- 방문 순서 자동 최적화
- 작성 중 코스 임시 저장
- 추천 코스 관리 기능

후속 공개 기능에서는 `isPublic`을 사용한다. `false`는 작성자만 조회할 수 있고, `true`는 공개 코스 조회 정책에 따라 다른 사용자도 볼 수 있게 한다.

## 14. 1차 구현 완료 조건

- [ ] 특정 내 픽 폴더에서 코스 생성 화면으로 이동할 수 있다.
- [ ] `전체` 탭과 상점 2개 미만 폴더에서는 코스를 만들 수 없다.
- [ ] 폴더명과 폴더 상점이 생성 화면의 초기값으로 표시된다.
- [ ] 상점 2~10개를 선택하고 방문 순서를 변경할 수 있다.
- [ ] 상점별 메모를 선택적으로 작성할 수 있다.
- [ ] 키보드로도 상점 순서를 변경할 수 있다.
- [ ] 저장 전에는 코스 문서가 생성되지 않는다.
- [ ] 같은 사용자와 폴더 조합으로 삭제되지 않은 코스가 둘 이상 생성되지 않는다.
- [ ] 생성 성공 후 생성된 코스 상세 화면으로 이동한다.
- [ ] 코스 상세에서 순서가 있는 마커와 상점 목록을 확인할 수 있다.
- [ ] 거리와 소요 시간에 가짜 값을 표시하지 않는다.
- [ ] 사용자는 자신의 코스 목록을 조회할 수 있다.
- [ ] 사용자는 자신의 코스를 수정하고 삭제할 수 있다.
- [ ] 다른 사용자의 비공개 코스 접근은 `403`을 반환한다.
- [ ] 원본 폴더를 삭제해도 코스는 유지되고 `sourceFolderId`만 정리된다.
- [ ] 코스를 삭제한 뒤 같은 폴더로 새 코스를 만들 수 있다.
- [ ] 비활성 상점은 자동 삭제하지 않고 이용 불가 상태로 표시한다.
- [ ] 생성·수정 실패 후 입력 내용이 유지된다.
