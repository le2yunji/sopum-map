# 코스 페이지 기능 설명

## 1. 목적

사용자가 내 픽 폴더에 저장한 소품샵 중 같은 지역에 있는 상점으로 하나의 소품 산책 코스를 만들고, 생성한 코스를 조회·수정·삭제할 수 있게 한다.

현재 구현은 개인 코스 관리, TMAP 도보거리 기반 추천 방문 순서, 코스 공개와 좋아요 저장을 제공한다. 공개 코스 탐색·검색과 실제 도보 경로 형상 표시는 후속 범위다.

## 2. 핵심 규칙

- 내 픽 폴더에는 여러 `regionGroup`의 상점이 함께 들어갈 수 있다.
- 하나의 코스에는 같은 `regionGroup`의 상점만 포함할 수 있다.
- 한 폴더에서는 지역별로 코스를 하나씩 만들 수 있다.
- 코스에는 같은 지역의 상점이 최소 2개, 최대 6개 필요하다.
- 코스의 `regionGroup`은 생성 후 변경할 수 없다.
- 코스는 생성 시점의 폴더 상태를 복사한 뒤 원본 폴더와 독립적으로 관리한다.
- 코스를 만든 뒤 폴더의 상점이 바뀌어도 기존 코스는 자동으로 바뀌지 않는다.
- `전체` 픽 목록에서는 코스를 만들 수 없다. 특정 폴더를 선택해야 한다.
- 사용자 생성 코스는 비공개로 생성되며 작성자가 상세 화면에서 공개 여부를 바꿀 수 있다.
- 추천 코스는 항상 공개하며 작성자를 `소품지도`로 표시한다.

## 3. 데이터 의미

### 코스 구분 필드

| 필드             | 의미                                       | 1차 구현 값        |
| ---------------- | ------------------------------------------ | ------------------ |
| `courseType`     | 사용자 생성 코스인지 추천 코스인지 구분    | `user_created`     |
| `sourceFolderId` | 코스 생성에 사용한 원본 내 픽 폴더         | 선택한 폴더 ID     |
| `regionGroup`    | 코스에 포함할 수 있는 상점의 고정 지역     | 사용자가 선택한 값 |
| `isPublic`       | 다른 사용자가 코스를 조회할 수 있는지 구분 | `false`            |

`isPublic`은 출처 필드가 아니라 공개 범위 필드다. `false`인 사용자 코스는 작성자만 상세 내용을 볼 수 있다.

### 지역 계약

- `regionGroup`은 상점과 같은 공용 타입을 사용한다.
- 현재 `SHOP_REGION_GROUPS`에 정의된 값만 사용하고 새로운 지역 키워드는 추가하지 않는다.
- 코스 제목의 기본값은 폴더명이다.
- 지역명은 제목에 붙이지 않고 별도 태그로 표시한다.
- 제목이 같은 지역별 코스를 구분할 수 있도록 코스 목록, 상세, 생성·수정 화면과 지역 선택 화면에 지역 태그를 항상 표시한다.

## 4. 사용자 흐름

### 코스 생성 또는 수정 진입

```text
내 픽 화면
→ 특정 폴더 선택
→ 이 폴더로 코스 만들기
→ 생성 가능한 지역과 기존 지역 코스 확인
→ 필요한 경우 지역 선택
→ /courses/new?folderId={folderId}&regionGroup={regionGroup}
  또는 /courses/{courseId}/edit
```

- 코스는 생성 화면에 진입할 때 만들지 않는다.
- 사용자가 `코스 만들기`를 눌러 유효한 요청을 제출했을 때만 데이터베이스에 저장한다.
- 저장 성공 후 생성된 코스 상세 화면으로 이동한다.
- 상세 화면에서 `코스가 만들어졌어요` 안내를 잠시 표시한다.

### 지역 선택

- 현재 폴더에서 생성 가능한 지역과 폴더에 연결된 기존 지역 코스를 함께 보여준다.
- 생성 가능한 지역은 코스 후보 상점이 2개 이상인 지역이다.
- 생성 가능한 새 지역이 하나뿐이고 기존 코스도 없으면 해당 지역의 상점 선택 단계로 바로 이동한다.
- 선택할 수 있는 지역이 여러 개면 지역 선택 화면을 표시한다.
- 기존 코스가 있는 지역을 선택하면 `/courses/{courseId}/edit`로 이동한다.
- 기존 코스가 없는 지역을 선택하면 새 코스 생성 화면으로 이동한다.
- 폴더에서 해당 지역 상점을 모두 제거했더라도 연결된 기존 코스는 지역 목록에 계속 표시한다.
- 기존 코스 수정 시 현재 폴더 상태를 코스에 자동 반영하지 않는다.

지역별 상태 예시:

| 상태                                | 표시와 동작                       |
| ----------------------------------- | --------------------------------- |
| 같은 지역 후보 상점 2개 이상       | `새 코스 만들기`                  |
| 해당 지역 코스가 이미 존재         | `코스 수정하기`                   |
| 같은 지역 후보 상점 1개            | 비활성화, `상점 1개 더 필요`       |
| 해당 지역 후보 상점 없음           | 새 생성 대상에서는 제외           |
| 후보는 없지만 기존 지역 코스가 존재 | 기존 코스 수정 진입로는 계속 표시 |

### 생성할 수 없는 폴더

- `전체` 탭에서는 코스 생성 동작을 제공하지 않는다.
- 같은 지역의 후보 상점이 2개 이상인 지역이 없으면 새 코스를 만들 수 없다.
- `같은 지역의 상점을 2개 이상 저장해 주세요`라는 이유를 안내한다.

## 5. 코스 생성·편집 화면

### 기본 입력값

- 제목은 폴더명으로 자동 입력하며 사용자가 수정할 수 있다.
- 지역은 제목과 분리된 태그로 표시한다.
- 설명은 선택 입력이다.
- 선택한 지역의 후보 상점이 2~10개면 모두 기본으로 선택한다.
- 후보 상점이 11개 이상이면 폴더에 먼저 추가한 순서로 10개를 기본 선택하고 나머지는 미선택으로 표시한다.
- 사용자는 기본 선택 결과를 바꿀 수 있다.

### 생성 시 상점 선택

- 원본 폴더에 들어 있는 상점 중 선택한 `regionGroup`과 같은 상점만 후보로 표시한다.
- 최종적으로 2~10개를 선택해야 한다.
- `active` 상점은 선택할 수 있다.
- `temporarily_closed` 상점은 현재 상태를 경고하고 선택할 수 있다.
- `hidden`, `closed` 상점은 새 코스 후보에서 제외한다.
- 위도·경도 위치 정보가 없는 상점은 후보에서 제외하고 이유를 안내한다.

### 수정 시 상점 선택

- 기존 `course.regionGroup`은 고정하며 수정 요청으로 변경할 수 없다.
- 새 상점은 현재 사용자의 내 픽 전체에서 기존 코스와 같은 `regionGroup`인 상점만 추가할 수 있다.
- 새로 추가하는 상점에는 생성 시와 같은 상태·위치 규칙을 적용한다.
- 상점 정보가 나중에 변경되어 기존 코스 지역과 달라졌더라도 해당 상점을 자동 삭제하지 않는다.
- 지역이 달라진 기존 상점은 경고를 표시하고 사용자가 직접 유지하거나 제거하게 한다.
- 코스는 원본 폴더와 독립적이므로 편집 화면에서 기존 상점을 제외할 수 있다.

### 추천 방문 순서

- 선택된 상점 사이의 TMAP 도보거리 행렬로 전체 이동 거리가 가장 짧은 방문 순서를 계산한다.
- 출발점은 고정하지 않는다. 전체 이동 거리가 가장 짧아지는 두 끝점을 자동으로 정한다.
- 정방향과 역방향의 거리는 같으므로 `순서 뒤집기` 동작을 제공한다.
- 터치 환경에서는 드래그로 방문 순서를 변경할 수 있다.
- 키보드와 보조 기술 사용자를 위해 위로 이동·아래로 이동 버튼을 함께 제공한다.
- 사용자가 수동으로 바꾼 순서를 자동으로 덮어쓰지 않는다.
- 상점을 추가하거나 제거하면 추천 순서를 다시 계산할지 확인한다.
- `추천 순서로 다시 정렬` 동작을 제공한다.
- 최종 화면 순서를 `Course.shops[].order`에 1부터 연속된 숫자로 저장한다.

추천 경로 계산은 UI와 분리된 인터페이스로 둔다.

```text
상점 좌표 목록
→ 추천 경로 계산기
→ 방문 순서와 총 거리
```

1차에는 TMAP Matrix API의 보행 거리와 예상 소요 시간을 사용한다. 상세 경로 좌표는 조회하거나 저장하지 않는다.

### 상점별 메모

- 각 상점에 선택적으로 메모를 작성할 수 있다.
- 예: `점심 전에 방문`, `스티커 코너 확인`.
- 메모는 현재 모델 기준 최대 300자다.

### 편집 가능한 항목

- 코스 제목
- 코스 설명
- 코스에 포함할 상점
- 방문 순서
- 상점별 메모

`sourceFolderId`와 `regionGroup`은 편집할 수 없다.

### 작성 중 이탈

- 사용자가 내용을 변경한 뒤 화면을 나가려고 하면 `작성 중인 내용이 사라져요` 확인창을 표시한다.
- 1차 구현에서는 임시 저장과 자동 저장을 제공하지 않는다.

## 6. 지역과 고유성

### 같은 지역 검증

- 생성 요청은 사용자가 선택한 `regionGroup`을 명시한다.
- 서버는 요청의 모든 상점이 해당 `regionGroup`과 같은지 검증한다.
- 여러 지역의 상점이 섞인 요청은 저장하지 않는다.
- 수정 요청에는 `regionGroup`을 받지 않는다.
- 수정 시 새로 추가하는 상점은 기존 `course.regionGroup`과 같은지 검증한다.
- 서울 같은 임의 기본 지역을 사용하지 않는다.

### 지역별 코스 고유성

- 사용자 생성 코스는 `userId + sourceFolderId + regionGroup` 조합마다 하나만 존재할 수 있다.
- 프론트엔드 확인만으로 중복 생성을 막지 않고 데이터베이스 고유 인덱스로도 보장한다.
- `sourceFolderId: null`인 코스는 고유성 대상에서 제외한다.
- 생성 경쟁으로 충돌하면 같은 폴더와 지역의 기존 `courseId`를 응답에서 식별할 수 있어야 한다.

## 7. 코스 상세 화면

### 표시 정보

- 코스 제목
- 코스 설명
- 고정 지역 태그
- 추천 방문 순서
- 상점 기본 정보와 현재 상태
- 상점별 메모
- 상점 상세 화면 링크
- 상점별 네이버 지도 길찾기 링크
- 작성자 이름과 생성일
- 작성자에게는 공개 상태와 받은 좋아요 수
- 다른 사용자에게는 좋아요 버튼과 받은 좋아요 수
- 상단 이전 화면, 공유, 소유자용 더보기 액션

### 상세 액션

- 공유는 Web Share API를 먼저 사용하고 지원되지 않거나 실패하면 클립보드 복사를 시도한다.
- 공유와 복사가 모두 실패하면 스낵바로 안내한다.
- 작성자는 좋아요 버튼 대신 공개 상태를 변경할 수 있다.
- 작성자의 코스 수정과 삭제는 상단 더보기 바텀시트에서 제공한다.
- 상점 행의 오른쪽 화살표를 누르면 `상점 보기`와 `길찾기`를 바텀시트로 제공한다.

### 지도와 거리

1차 구현에는 여러 상점을 잇는 실제 도보 경로 형상 API가 없다.

- 지도에 방문 순서가 표시된 마커를 배치한다.
- 마커를 저장된 방문 순서대로 직선으로 연결한다.
- 지도는 코스 전체를 보여 주는 고정 미리보기로 제공하며 확대·축소·이동을 지원하지 않는다.
- 직선은 방문 순서만 표현하며 실제 보행 경로로 안내하지 않는다.
- 코스를 저장할 때 최종 방문 순서를 기준으로 구간별 도보 거리와 예상 소요 시간을 저장한다.
- 상세 화면의 상점 카드 사이에는 직전 상점부터의 도보 거리와 예상 소요 시간을 표시한다.
- 첫 번째 상점은 출발 위치가 정해지지 않았으므로 구간 정보를 표시하지 않는다.
- 각 상점에서 기존 네이버 지도 길찾기 링크를 사용할 수 있다.
- 상점 구성이 변경되면 구간 정보를 다시 계산하고, 제목·설명만 바뀌면 기존 값을 유지한다.
- 기존 데이터에 구간 정보가 없으면 가짜 값을 만들지 않고 안내를 숨긴다.

### 실제 도보 경로 형상 도입 이후

- 지도와 같은 제공사의 도보 경로 형상을 사용할 수 있을 때 도입을 검토한다.
- 경로 계산 제공사와 지도 제공사가 다르면 확대 화면에서 도로 좌표가 어긋날 수 있으므로 혼용하지 않는다.
- 기존 코스의 저장 순서는 자동으로 바꾸지 않는다.
- 사용자가 `도보 기준 추천 순서로 다시 정렬`을 실행했을 때만 새 순서를 적용한다.
- API 비용이나 응답 속도 문제가 생기면 계산 결과 캐시를 별도로 검토한다.

### 이용 불가능하거나 정보가 변경된 상점

- 기존 코스의 상점이 `hidden`, `temporarily_closed`, `closed` 상태가 되어도 자동으로 삭제하지 않는다.
- 상세 화면에 현재 상태와 이용 가능 여부를 표시한다.
- 코스 지역과 상점의 현재 지역이 달라지면 경고를 표시한다.
- 위치 정보가 사라져 거리 계산을 완료할 수 없으면 계산 불가 상태를 안내한다.
- 코스 편집 화면에서 사용자가 직접 제거할 수 있다.
- 상점 변경 때문에 방문 순서와 작성자의 기록을 자동으로 바꾸지 않는다.

## 8. 내 코스와 찜한 코스 목록

- 마이페이지의 `/me/courses`에서 `내 코스`와 `찜한 코스` 탭을 제공한다.
- 코스 항목을 누르면 해당 코스 상세 화면으로 이동한다.
- 제목이 같은 지역별 코스를 구분할 수 있도록 지역 태그를 항상 표시한다.
- 목록은 20개 단위의 시간·`_id` 복합 커서로 다음 페이지를 불러온다.
- 내 코스 카드에는 공개 상태와 받은 좋아요 수를 표시한다.
- 공개된 찜 코스 카드에는 제목, 지역, 작성자와 좋아요 수를 표시한다.
- 찜한 코스가 나중에 비공개가 되면 제목·설명·지역·사진·상점·작성자·좋아요 수를 숨기고 `비공개 코스`로만 표시한다.
- 비공개 찜 카드를 누르면 `작성자가 비공개한 코스입니다.`를 안내하며 찜 해제는 허용한다.

## 9. 삭제와 원본 폴더의 관계

### 원본 폴더 삭제

- 원본 폴더를 삭제해도 해당 폴더에서 만든 모든 지역 코스는 유지한다.
- 연결된 코스들의 `sourceFolderId`만 `null`로 정리한다.
- 코스에 복사된 상점, 순서와 메모는 유지한다.

### 코스 삭제

- 코스 삭제 전 확인창을 표시한다.
- 코스를 삭제하면 연결된 좋아요도 함께 삭제한다.
- 코스가 삭제되면 해당 폴더와 지역 조합의 고유 제약이 풀린다.
- 사용자는 같은 폴더와 지역으로 새 코스를 다시 만들 수 있다.

## 10. 접근 권한

- 인증되지 않은 사용자가 내 코스 API에 접근하면 `401`을 반환한다.
- 다른 사용자의 비공개 코스에 접근하면 `403`을 반환한다.
- 코스 작성자만 코스를 수정하거나 삭제할 수 있다.
- 코스 작성자만 사용자 코스의 공개 여부를 바꿀 수 있다.
- 자신의 코스에는 좋아요할 수 없다.
- 다른 사용자의 공개 코스와 추천 코스에는 좋아요할 수 있다.
- 이미 비공개가 된 찜 코스도 좋아요를 해제할 수 있다.
- 다른 사용자의 내 픽 폴더로 코스를 만들 수 없다.
- 다른 사용자의 폴더를 사용한 생성 요청에는 기존 폴더 접근 정책과 같은 `403`을 반환한다.

## 11. 백엔드와 공용 계약 책임

### 백엔드 책임

- 폴더와 지역 기반 코스 생성
- 코스 상세 조회
- 내 코스 목록 조회
- 찜한 코스 목록 조회
- 코스 공개 여부 변경과 권한 확인
- 코스 좋아요 추가·해제와 중복 방지
- 작성자, 좋아요 여부와 좋아요 수를 포함한 상세 표시 모델
- 코스 수정과 삭제
- 폴더 및 코스 소유자 검증
- 상점 존재 여부, 상태, 위치와 지역 검증
- 상점 개수와 중복 검증
- 방문 순서 검증
- 코스 지역 변경 방지
- 폴더와 지역 조합마다 코스 하나 보장
- 폴더 삭제 시 연결된 모든 코스의 `sourceFolderId` 정리

### 폴더별 기존 코스 확인 계약

폴더 하나에 여러 지역 코스가 연결될 수 있으므로 단일 `courseId`만 반환해서는 안 된다. 폴더 목록 또는 별도 조회 계약에서 지역별 연결 정보를 제공한다.

```ts
type PickFolderCourse = Readonly<{
  courseId: string;
  regionGroup: ShopRegionGroup;
}>;
```

프론트엔드는 이 데이터를 사용해 지역마다 `새 코스 만들기`와 `코스 수정하기`를 구분한다.

### 생성 API 입력

생성 요청에는 최소한 다음 값이 필요하다.

- `sourceFolderId`
- `regionGroup`
- `title`
- `description`
- 선택한 상점 ID 목록
- 상점별 방문 순서
- 상점별 선택 메모

서버는 클라이언트가 보낸 `regionGroup`과 실제 상점 지역이 모두 같은지 검증한다. `courseType`은 `user_created`로 고정하고, `isPublic`은 생성 화면의 사용자 선택값을 저장한다. 생성 화면의 기본값은 `false`다.

## 12. 오류 처리

- 코스 생성·수정 실패 시 사용자가 입력한 제목, 설명, 순서와 메모를 유지한다.
- 화면 안에서 오류 원인을 안내하고 `다시 시도` 동작을 제공한다.
- 상점이 2개보다 적거나 10개보다 많으면 저장하지 않는다.
- 같은 상점을 중복으로 포함할 수 없다.
- 방문 순서는 1부터 상점 개수까지 중복 없이 연속되어야 한다.
- 존재하지 않는 상점은 코스에 추가할 수 없다.
- 다른 지역의 상점이 섞인 요청은 저장하지 않는다.
- 위치 정보가 없는 상점으로 새 코스를 생성할 수 없다.
- `hidden`, `closed` 상점은 새 코스에 추가할 수 없다.
- 같은 폴더와 지역의 코스가 이미 있으면 기존 `courseId`를 식별할 수 있는 충돌 응답을 제공한다.

## 13. 현재 구현에서 제외하는 기능

- 공개 코스 목록과 검색
- 공개 코스 신고와 관리
- 실제 도보·대중교통 경로 형상 표시
- 작성 중 코스 임시 저장
- 추천 코스 관리 기능

현재는 공유받은 공개 코스 상세를 조회할 수 있다. 공개 코스를 서비스 안에서 찾아보는 탐색·검색 화면은 별도 후속 범위다.

## 14. 1차 구현 완료 조건

- [ ] 특정 내 픽 폴더에서 지역별 코스 생성 또는 기존 코스 수정 흐름으로 이동할 수 있다.
- [ ] 내 픽 폴더에는 여러 지역의 상점을 함께 저장할 수 있다.
- [ ] 같은 지역의 후보 상점이 2개 미만이면 새 코스를 만들 수 없다.
- [ ] 생성 가능한 지역이 여러 개면 지역을 선택할 수 있다.
- [ ] 한 폴더에서 지역별로 코스를 하나씩 만들 수 있다.
- [ ] 코스의 모든 상점이 하나의 `regionGroup`에 속한다.
- [ ] 코스 생성 후 `regionGroup`을 변경할 수 없다.
- [ ] 폴더명과 선택 지역의 후보 상점이 생성 화면의 초기값으로 표시된다.
- [ ] 지역은 제목이 아닌 별도 태그로 주요 화면에 표시된다.
- [ ] 상점 2~10개를 선택할 수 있다.
- [ ] TMAP 도보거리 기반 추천 방문 순서를 적용할 수 있다.
- [ ] 추천 순서를 뒤집거나 수동으로 변경하고 다시 계산할 수 있다.
- [ ] 상점별 메모를 선택적으로 작성할 수 있다.
- [ ] 키보드로도 상점 순서를 변경할 수 있다.
- [ ] 저장 전에는 코스 문서가 생성되지 않는다.
- [ ] 같은 사용자·폴더·지역 조합으로 코스가 둘 이상 생성되지 않는다.
- [ ] 생성 성공 후 생성된 코스 상세 화면으로 이동한다.
- [ ] 코스 상세에서 순서가 있는 마커와 상점 목록을 확인할 수 있다.
- [ ] 코스 지도는 고정 미리보기로 표시되고 마커 사이를 직선으로 연결한다.
- [ ] 방문 순서 사이에 도보 거리와 예상 소요 시간을 표시한다.
- [ ] 예상 소요 시간에 가짜 값을 표시하지 않는다.
- [ ] 사용자는 자신의 코스 목록을 조회할 수 있다.
- [ ] 사용자는 자신의 코스를 수정하고 삭제할 수 있다.
- [ ] 다른 사용자의 비공개 코스 접근은 `403`을 반환한다.
- [ ] 원본 폴더를 삭제해도 연결된 모든 코스는 유지되고 `sourceFolderId`만 정리된다.
- [ ] 코스를 삭제한 뒤 같은 폴더와 지역으로 새 코스를 만들 수 있다.
- [ ] 비활성 상점과 지역이 변경된 기존 상점은 자동 삭제하지 않고 상태를 표시한다.
- [ ] 생성·수정 실패 후 입력 내용이 유지된다.
- [x] 작성자는 자신의 코스를 공개 또는 비공개로 바꿀 수 있다.
- [x] 공개 코스와 추천 코스에 좋아요를 추가하거나 해제할 수 있다.
- [x] 코스 상세에 작성자, 공개 상태, 좋아요 수와 사용자별 좋아요 상태를 표시한다.
- [x] 내 코스와 찜한 코스를 20개 단위 커서 목록으로 조회한다.
- [x] 비공개로 바뀐 찜 코스는 민감한 정보를 숨기고 찜 해제만 허용한다.
- [x] 코스 상세의 수정·삭제와 상점 액션을 바텀시트로 제공한다.
