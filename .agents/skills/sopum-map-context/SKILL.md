# 소품지도 작업 맥락 구성

## 기본 절차

1. 저장소 루트의 `AGENTS.md`를 끝까지 읽는다.
2. `MEMORY.md`에서 구조와 기록 시점의 구현 상태를 확인한다.
3. 더 가까운 경로에 `AGENTS.md`가 있으면 해당 영역 작업에 함께 적용한다.
4. `git status --short --branch`와 최근 Git 로그로 현재 상태를 확인한다.
5. 진행 중인 브랜치를 이어가는 요청이면 `git worktree list`와 관련 워크트리의 미커밋 변경도 확인한다.
6. 요청과 관련된 소스, 타입, 테스트, 설정 파일만 골라 읽는다.
7. `MEMORY.md`와 실제 코드가 다르면 실제 코드를 우선하고 차이를 사용자에게 알린다.

## 영역별 맥락

- 프론트엔드 작업: `frontend/AGENTS.md`, 해당 App Router 페이지, 관련 컴포넌트와 Storybook 스토리를 읽는다. `docs/superpowers/specs/`와 `docs/superpowers/plans/`에 관련 설계·계획이 있으면 함께 확인한다.
- 백엔드 작업: 라우터, 컨트롤러, 서비스, 검증, 모델과 관련 공용 타입을 흐름대로 읽는다.
- API 계약 작업: `packages/shared`의 export 진입점과 프론트·백엔드 소비 코드를 함께 확인한다.
- Git 또는 PR 작업: 기준 브랜치, 변경 파일, 사용자 소유의 미커밋 변경을 먼저 확인한다.

## 결과 정리

작업을 시작하기 전에 필요한 경우 다음 내용을 짧게 정리한다.

- 현재 브랜치와 작업 트리 상태
- 병합 완료, 별도 브랜치, 미커밋 작업을 구분한 진행 상태
- 관련 패키지와 핵심 파일
- 이미 구현된 내용과 빠진 내용
- 확인한 명령어와 제약
- 문서와 코드 사이의 불일치

추측으로 빈 요구사항을 채우지 않는다. 작업 방향을 바꿀 정도의 불일치는 사용자에게 확인한다.

구조나 구현 상태가 달라지는 작업을 마치면 `MEMORY.md`의 관련 항목도 확인한다. 스냅샷을 갱신할 때는 기준일, 기준 브랜치와 기준 커밋을 함께 바꾼다.
